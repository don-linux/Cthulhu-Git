# Adversarial report for 0.0.2

Pass run against `0.0.2` plus the repository-view layout, before the next
release. Seven areas, listed in [../ADVERSARIAL-TESTING.md](../ADVERSARIAL-TESTING.md).
The suite is `cargo test --locked`. Findings below are the ones that failed
or that came from reading the workflows. Everything else in those files passed.

## Fixed

| Id | Severity | What was wrong | Fix |
| -- | -------- | -------------- | --- |
| A1 | Critical | `git status` on open ran `filter.*.clean` and `filter.*.process`, including a filter installed only through `include.path`. | HEAD is read with `symbolic-ref` and `rev-parse`. Status is not run. |
| D1 | Critical | `save_to` opened `settings.json.<pid>.tmp` with `File::create`, which follows a symlink and truncates the target. | Unlink the temp path, then open it with `create_new`. |
| A2 | High | `GIT_REPLACE_REF_BASE` replaced the commit subject and hid the parent. | `--no-replace-objects`, and the variable is removed. |
| A3 | High | `GIT_SHALLOW_FILE` dropped parent commits. | The variable is removed. |
| A4 | High | `GIT_GRAFT_FILE` dropped parent commits. | The variable is removed. |
| A8, C2 | High | One `git --version` that slept blocked discovery, including a later working git. | A probe is killed after 250 ms and the search continues. An override that times out is an error. |
| A9 | High | 32 MiB of `rev-parse` stdout was used as a path. | Stdout and stderr are capped at 8 MiB. |
| B1 | High | A bare repository failed as "this operation must be run in a work tree". | `--is-bare-repository` selects `--absolute-git-dir`, and HEAD is still read. |
| B2 | High | A directory whose name ended in CR or LF could not be opened. `show_toplevel` stripped every trailing CR and LF. | Only the newline Git added is stripped. On Windows, one CR from CRLF is stripped too. |
| C1 | High | `CTHULHU_GIT=git` passed the cwd execute-bit check and then ran a different `git` from `PATH`. | The bare name is spawned as `./git`. The reported path stays the one that was set. |
| D2 | High | Two threads shared `settings.json.<pid>.tmp` and could publish torn or empty JSON. | Saves in one process take a lock, and the temp file is created with `create_new`. |
| D3 | High | A UTF-8 BOM, as written by Notepad, made the whole settings file a parse error. | The BOM is skipped before JSON parsing. The file is not rewritten. |
| A5, G3 | Medium | Any stderr containing "not a git repository" became `NotARepository`, including a dubious-ownership error whose path contained those words. Git 2.15's `fatal: Not a git repository` did not match. | Only a line that starts with that fatal matches, case-insensitively. |
| A6, A7, G2 | Medium | The suggested `safe.directory` command was not quoted. A newline in the path ran a second command under `sh -c`. An apostrophe truncated the path. | The path is parsed from git's quoted hint when present, and the suggestion is single-quoted. |
| C3 | Low | `2.15.0-rc0` counted as 2.15.0. `--no-optional-locks` arrived in the final release. | A `-rc`, `-alpha`, `-beta`, or `-pre` suffix is below the floor. `.windows` and `.vfs` still count. |
| C4 | Medium | A `PATH` entry wrapped in quotes was skipped, because it did not look absolute. | One surrounding pair of quotes is removed before that check. |
| C5 | Medium | Finder's `-psn_…` argument was opened as the startup folder. | An argument that starts with `-` is ignored. |
| D4 | Medium | `"recent_repositories": null` rejected the whole file. | JSON `null` is the empty list. |
| G4 | Low | `repository at ''` produced an empty path instead of the directory git was pointed at. | An empty quoted path falls back to that directory. |
| A10 | Low | Inherited `GIT_TRACE` created a file during open. | `GIT_TRACE`, `GIT_TRACE2`, `GIT_TRACE2_EVENT`, `GIT_TRACE2_PERF`, and `GIT_TRACE_PACKET` are removed. |
| F3 | High | `cargo test` ran only on Ubuntu. | CI also runs it on `windows-latest` and `macos-latest`. |
| F4, F5 | Medium | `inputs.label` was interpolated into `run:` scripts, and third-party actions were pinned to moving tags. `softprops/action-gh-release` publishes with `contents: write`. | `LABEL` is an environment variable. Actions are pinned to the commit of the tag that was current on 2026-10-01. |

## Accepted

| Id | Severity | Why it stays |
| -- | -------- | ------------ |
| G1 | Low | `short_oid` returns the whole string when byte 12 is inside a multibyte character, instead of a shorter prefix. Git object ids are ASCII hex, so real commits are unaffected. Covered by `short_oid_mid_character_returns_the_entire_string`. |
| E1 | Medium | A recent repository that has been deleted stays on the home screen. Opening it shows the error and does not crash. The entry is not removed. Noted in the README limits. |
| F1, F2 | High, residual | Pinning the publish actions removes the moving-tag swap. A person who can push a `v*` tag can still publish whatever workflow that commit contains. The verify job's "must be on main" check lives in the tagged commit, so it is not an independent gate. Tag protection belongs on the repository, not in this workflow. |
| F6 | Medium | The `.deb` is installed in CI. The `.rpm`, Windows `.exe`, and macOS app are not launched. `cargo test` now runs on those OS images; a GUI smoke of the package is still missing. |
| F7 | Medium | `action-gh-release` updates an existing release and overwrites files. Pushing the same tag again republishes. |

## Checked and already safe

Aliases of `status`, `rev-parse`, and `log` did not run. `core.pager`, `core.fsmonitor`, and `core.hooksPath` did not run. `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, and `GIT_EXEC_PATH` did not redirect the repository or execute a command. A settings symlink (the settings path itself, not the temp file) is replaced by `rename` and does not write through to an outside target. Corrupt settings are not overwritten on startup. Home does not forget `last_repository`. SHA-256 repos, worktrees, submodules, shallow clones, packed-refs, and a 1 MiB subject open. `actionlint` 1.7.12 was clean. `desktop-file-validate` and `plistlib` accepted the packaging files.

Cross `cargo check --locked` for `x86_64-pc-windows-gnu` and `x86_64-apple-darwin` succeeded. A Git 2.15.0 built under `/tmp` showed two separate things: `tests/repo.rs` uses `git init -b`, which needs Git 2.28, so those fixtures are not a 2.15 run; and 2.15 prints `Not a git repository`, which the classifier now matches.
